# Security Policy

Security reports are welcome. Do not publish secrets, active credentials, personal data, or exploit details that could endanger users in a public issue.

## Reporting

Use GitHub private vulnerability reporting or the repository security-advisory workflow when available. If a private reporting path is not available, do not post sensitive exploit details publicly.

For ordinary non-security bugs, use the normal issue tracker when it is enabled.

## Remove sensitive data before submitting

Do not include passwords, access or refresh tokens, session cookies, authorization codes, client secrets, private keys, signing material, recovery codes, payment credentials, database credentials, infrastructure credentials, private endpoints, personal information, or unsanitized logs and screenshots.

## Public examples and documentation

Examples must use placeholders. Public documentation should describe security-sensitive behavior only at the level needed for legitimate use, integration, interoperability, troubleshooting, or responsible security review.

## Scope

Security policy details may evolve as the Leviathan ecosystem moves from private development toward wider testing and release.
